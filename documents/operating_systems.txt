================================================================================
                     OPERATING SYSTEMS (OS)
================================================================================

1. DEFINITION AND ROLE
----------------------
An operating system is system software that manages computer hardware, software
resources, and provides common services for computer programs. It acts as an
intermediary between users, applications, and the hardware.

Core functions:
- Process management
- Memory management
- File system management
- I/O device management
- User interface (CLI/GUI)
- Security and protection

2. OPERATING SYSTEM STRUCTURES
-------------------------------
- Monolithic Kernel: all OS services run in kernel space (e.g., Linux, Unix).
- Microkernel: minimal kernel, most services run as user-space processes (e.g.,
  Minix, QNX).
- Hybrid Kernel: combines monolithic and microkernel approaches (e.g., Windows NT).
- Exokernel: provides hardware abstraction, leaves resource management to
  applications.
- Modular kernel: loadable modules for device drivers and services (e.g., Linux
  modules).

3. PROCESS MANAGEMENT
---------------------
A process is a program in execution. It contains:
- Program code (text section)
- Data section (static variables)
- Heap (dynamic memory)
- Stack (function calls)
- Process Control Block (PCB): stores process state, registers, program counter,
  scheduling info, etc.

Process states: New, Ready, Running, Waiting, Terminated.
Context switching: saving/restoring process state when switching between processes.

Process scheduling:
- Long-term scheduler: selects processes to be admitted into the system.
- Short-term scheduler (CPU scheduler): selects which ready process runs next.
- Scheduling algorithms:
  - First-Come First-Served (FCFS)
  - Shortest Job Next (SJN)
  - Priority Scheduling
  - Round Robin (time-sliced)
  - Multilevel Queue Scheduling
  - Multilevel Feedback Queue

4. THREADS
-----------
A thread is the smallest unit of execution within a process. Threads share the
process's code and data but have their own stack and registers.
- User-level threads: managed by the user library, OS unaware.
- Kernel-level threads: managed by the OS kernel.
- Many-to-One, One-to-One, Many-to-Many threading models.
- Concurrency vs. Parallelism.

5. MEMORY MANAGEMENT
--------------------
Memory management involves allocation, protection, and virtual memory.

- Physical memory: actual RAM.
- Logical (virtual) address space: generated by CPU, translated by MMU.
- Contiguous vs. Non-contiguous allocation.
- Paging: divides memory into fixed-size frames (physical) and pages (logical).
- Segmentation: variable-sized segments.
- Page table and TLB (Translation Lookaside Buffer).

Virtual memory:
- Demand paging: pages loaded only when needed.
- Page replacement algorithms: FIFO, LRU, Optimal, Clock, Second-chance.
- Thrashing: excessive page swapping.

6. FILE SYSTEMS
----------------
File systems organize data on storage devices.
- File attributes: name, size, permissions, timestamps.
- Directory structure: single-level, two-level, tree, acyclic graph.
- File allocation methods: contiguous, linked, indexed.
- Common file systems: ext4 (Linux), NTFS (Windows), APFS (macOS), ZFS, FAT32.

7. I/O SYSTEMS
---------------
- Device drivers: software that communicates with hardware controllers.
- I/O methods: polling, interrupt-driven, DMA (Direct Memory Access).
- I/O scheduling: to optimize disk access, e.g., SCAN, C-SCAN, SSTF.
- Buffering, caching, and spooling.

8. SECURITY AND PROTECTION
---------------------------
- Authentication: verifying user identity (passwords, biometrics).
- Authorization: permissions (read, write, execute) per user/group.
- Protection mechanisms: access control lists (ACLs), capabilities.
- Secure boot, encryption (full-disk, file-level), sandboxing.

9. INTERPROCESS COMMUNICATION (IPC)
-----------------------------------
- Shared memory: fastest, but requires synchronization.
- Message passing: pipes, FIFOs, message queues, sockets.
- Signals: asynchronous notifications.
- Remote Procedure Calls (RPC).

10. VIRTUALIZATION AND CONTAINERS
---------------------------------
- Hypervisors (Type 1 bare-metal, Type 2 hosted) allow multiple OS instances.
- Virtual machines emulate full hardware.
- Containers (Docker, LXC) share OS kernel but isolate user space.
- Benefits: resource efficiency, isolation, portability.

11. DEADLOCKS
-------------
- Conditions: Mutual exclusion, Hold and wait, No preemption, Circular wait.
- Deadlock handling: prevention, avoidance (Banker's algorithm), detection and
  recovery, and ignorance (Ostrich algorithm).

12. DISTRIBUTED SYSTEMS
------------------------
- A collection of independent computers that appear as a single system.
- Challenges: network latency, partial failures, consistency.
- Models: client-server, peer-to-peer.
- Middleware (CORBA, gRPC).

13. POPULAR OPERATING SYSTEMS
------------------------------
- Linux: open-source kernel, used in servers, embedded, Android.
- Windows: Microsoft, dominant on PCs and servers.
- macOS: Apple's proprietary, Unix-based.
- FreeBSD, OpenBSD: Unix-like, focus on stability/security.
- Real-time OS (RTOS): VxWorks, FreeRTOS for embedded.

14. EMERGING TRENDS
-------------------
- Edge OS: lightweight OS for IoT devices.
- Embedded OS: tiny kernels for microcontrollers.
- Confidential computing: trusted execution environments (TEEs).
